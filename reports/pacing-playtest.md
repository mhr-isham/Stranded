# TIME-14 · Chapter 1 pacing playtest

The proposed 75–80 minutes for Ground → Sky → Blue Planet → Moon → Flight is a hypothesis. Opening landing and briefing should be recorded separately. This report describes the test procedure. First-time human timing data has yet to be collected.

## Set up the runs

- Use Chapter 1, **Single expedition**, with the same seed across the first round. Seed **316** is a repeatable starting point. Use a second seed for a later round to check whether timing depends on the sky or terrain.
- Split first-time players between **Cadet** and **Navigator**. Use the same survival setting across that comparison and keep each mode’s normal guidance. A player who has already used the instruments or completed Flight School can still test the game, but mark the experience level in the notes.
- Before starting, open **Optional pacing playtest** and enable **Record local pacing**. Players can take breaks, explore, or stop at a save point. Play to the debrief if possible and keep partial reports if a run ends sooner.
- Open **Menu → Open local pacing report** to download from a live expedition. The title and debrief also offer the report for the current run. Download before starting another expedition.

## Read a report

- **Foreground** is focused, visible play time. Title screens, background tabs, Flight School and the pacing report itself are outside this total.
- **Scheduled waits** marks time when a clock stop was pending and the game clock was advancing. The player may have been working on another task at the same time. **Other warp** covers foreground play above 1× without a scheduled stop. Both sit inside foreground time.
- **After 60 seconds without input** is a reading aid. It can overlap waits and can include deliberate watching. It cannot establish that a player was idle.
- **Screen or activity** identifies where time went. Driving can be an enjoyable choice or a source of friction. Seeing a screen in the log cannot establish which.
- Use **First usable planner visit**, **First launch attempt**, **Destination landing recorded**, and **Debrief reached** to distinguish route preparation from flight and landing. Act completion markers record the first time the game recognized each milestone, including in runs later rewound.

## Discuss before tuning

Ask the player which moment felt unclear, which delay felt like a real expedition, and which activity they chose to keep doing. Keep notes optional. A run that takes longer because the player enjoys exploring calls for a different response from one that stalls on an unclear action.

Compare reports within each mode before drawing conclusions across modes. Look for repeated friction at the same point, then change one cause and retest. The recorder stores these totals locally and sends nothing automatically.
